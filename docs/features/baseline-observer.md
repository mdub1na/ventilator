# Независимое наблюдение исходного состояния SMC

## 1. Overview

После первой пробы `Ftst` немедленное чтение показало исходное состояние, а независимое чтение после завершения процесса обнаружило другое. Отдельная команда только для чтения наблюдает состояние в течение фиксированного интервала и сразу сообщает об отклонении. Она не входит в Ventilator.app и не восстанавливает управление вентиляторами.

## 2. Business rules

1. Команда `smc-write-trial observe-baseline --read-only` доступна только на `Mac15,7` с macOS 27.0 и двумя вентиляторами. Она не требует `sudo` и не имеет аргумента `--apply`. Для доступа к AppleSMC из песочницы Codex может потребоваться разрешение среды запуска; самой команде root не нужен.
2. Команда делает 61 снимок: при запуске, затем раз в секунду до отметки 60 секунд. Каждый успешный снимок содержит монотонное время, `Ftst`, режимы, цели и фактические RPM двух вентиляторов, `TCMz`, `Tg0D`, `TH0a` и результат проверки исходного состояния.
3. Исходное состояние означает `Ftst=0`, режимы `[3, 3]`, обе цели с абсолютным значением не выше 1 RPM. Нулевые фактические обороты допустимы. При отклонении команда печатает `alert` и завершается с ненулевым кодом без попытки записи.
4. При ошибке чтения любого обязательного значения команда печатает `alert` с причиной `read_failed` и завершается с ненулевым кодом. Ошибка ожидания между снимками даёт `wait_failed`, прерывание — `interrupted`; ни то ни другое не считается успешным наблюдением.
5. Результат `stable` подтверждает только значения, доступные в течение этого интервала. Он не доказывает восстановление после будущей записи, отсутствие более позднего изменения или способность вернуть управление системе.

## 3. Local contract

```text
smc-write-trial observe-baseline --read-only
```

JSON-события: `observe` для снимка, `alert` при отклонении/ошибке, `complete` после всего интервала. В командной ветке отсутствует вызов записи SMC.

## 3a. Проверка на устройстве

На `Mac15,7` с macOS 27.0 2026-09-26 команда `observe-baseline --read-only` выполнила все 61 чтение без `sudo`. Снимки с отметками 0–60 секунд показывали `Ftst=0`, режимы `[3,3]`, цели `[0,0]`; фактические RPM были `[0,0]`. Команда завершилась `{"event":"complete","samples":61,"status":"stable"}` с кодом 0. Первый запуск внутри песочницы Codex не смог открыть AppleSMC (`0xe00002e2`); после разрешения среде запуска read-only доступ появился. Записи SMC не выполнялись. Этот результат не проверяет поведение после новой записи.

После переноса цикла в отдельную тестируемую логику команда повторно прошла на той же модели и версии ОС: 61 снимок с отметками 0–60 за 60,46 секунды, каждый с `baseline=true`, итог `complete/stable`, код 0. Симуляция в unit-тесте обнаруживает состояние `Ftst=1`, режимы `[0,0]`, цели `[1350,1458]` на третьем снимке после двух исходных. Это проверка реакции кода на отложенное изменение, а не новое воспроизведение аппаратного случая.

## 5. Scenarios (BDD / test cases)

### Scenario: Исходное состояние сохраняется весь интервал
* **Given:** точная модель и версия ОС, обязательные ключи читаются.
* **When:** 61 снимок остаётся исходным.
* **Then:** команда печатает `complete` со статусом `stable` и завершается успешно.
* **Manual:** проверено запуском 2026-09-26 на `Mac15,7`/macOS 27.0, §3a.

### Scenario: Состояние изменилось между снимками
* **Given:** исходный снимок прочитан.
* **When:** следующий снимок показывает `Ftst=1`, режим не `3` или ненулевую цель.
* **Then:** команда печатает `alert` и завершается с ошибкой.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_catches_delayed_ftst_change`, `prototype/smc-write-trial/trial_actions_test.c#baseline_observation_rejects_changed_state`

### Scenario: Обязательное чтение не удалось
* **Given:** наблюдение началось.
* **When:** один из обязательных ключей недоступен.
* **Then:** команда печатает `alert` с `read_failed` и завершается с ошибкой.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_stops_on_read_failure`

### Scenario: Наблюдение прервано или ожидание не удалось
* **Given:** хотя бы один исходный снимок прочитан.
* **When:** процесс получает прерывание либо ожидание следующего снимка завершается ошибкой.
* **Then:** команда печатает `alert` с причиной `interrupted` либо `wait_failed` и завершается с ошибкой, без `complete/stable`.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_stops_on_interruption_or_wait_failure`

## 6. Limits

Этот режим не является внешним watchdog: он завершается через 60 секунд и не может восстановить состояние при ошибке, аварии процесса, сне или позднейшем изменении SMC. Длительность задержки после аппаратной записи пока неизвестна; само наблюдение без новой пробы не определит её предел.
