# Независимое наблюдение исходного состояния SMC

## 1. Overview

После первой пробы `Ftst` немедленное чтение показало исходное состояние, а независимое чтение после завершения процесса обнаружило другое. Отдельная команда только для чтения наблюдает состояние в течение фиксированного интервала и сразу сообщает об отклонении. Она не входит в Ventilator.app и не восстанавливает управление вентиляторами.

## 2. Business rules

1. Команда `smc-write-trial observe-baseline --read-only` доступна только на `Mac15,7` с macOS 27.0 и двумя вентиляторами. Она не требует `sudo` и не имеет аргумента `--apply`. Для доступа к AppleSMC из песочницы Codex может потребоваться разрешение среды запуска; самой команде root не нужен.
2. Команда делает 61 снимок: при запуске, затем с секундным ожиданием между чтениями. Поле `second` — номер шага 0–60. Каждый успешный снимок содержит время завершения чтения по `CLOCK_MONOTONIC_RAW`, `Ftst`, режимы, цели и фактические RPM двух вентиляторов, `TCMz`, `Tg0D`, `TH0a` и результат проверки исходного состояния. Для `stable` между первым и последним снимками должно пройти не менее 60 секунд.
3. Исходное состояние означает `Ftst=0`, режимы `[3, 3]`, обе цели с абсолютным значением не выше 1 RPM. Нулевые фактические обороты допустимы. При отклонении команда печатает `alert` и завершается с ненулевым кодом без попытки записи.
4. При ошибке чтения любого обязательного значения команда печатает `alert` с причиной `read_failed` и завершается с ненулевым кодом. Ошибка ожидания между снимками даёт `wait_failed`, прерывание — `interrupted`. Неизвестное, отрицательное или обратное время, чтение дольше пяти секунд, интервал между завершёнными снимками вне 0,9–5 секунд либо слишком короткое полное окно дают `timing_failed`; после этого `complete/stable` не печатается. Первый снимок также проверяется по длительности чтения.
5. Результат `stable` подтверждает только значения, доступные в течение этого интервала. Он не доказывает восстановление после будущей записи, отсутствие более позднего изменения или способность вернуть управление системе.

## 3. Local contract

```text
smc-write-trial observe-baseline --read-only
```

JSON-события: `observe` для снимка, `alert` при отклонении/ошибке, `complete` после всего интервала. В командной ветке отсутствует вызов записи SMC.

## 3a. Проверка на устройстве

На `Mac15,7` с macOS 27.0 2026-09-26 команда `observe-baseline --read-only` выполнила все 61 чтение без `sudo`. Снимки с отметками 0–60 секунд показывали `Ftst=0`, режимы `[3,3]`, цели `[0,0]`; фактические RPM были `[0,0]`. Команда завершилась `{"event":"complete","samples":61,"status":"stable"}` с кодом 0. Первый запуск внутри песочницы Codex не смог открыть AppleSMC (`0xe00002e2`); после разрешения среде запуска read-only доступ появился. Записи SMC не выполнялись. Этот результат не проверяет поведение после новой записи.

После переноса цикла в отдельную тестируемую логику команда повторно прошла на той же модели и версии ОС: 61 снимок с отметками 0–60 за 60,46 секунды, каждый с `baseline=true`, итог `complete/stable`, код 0. Симуляция в unit-тесте обнаруживает состояние `Ftst=1`, режимы `[0,0]`, цели `[1350,1458]` на третьем снимке после двух исходных. Это проверка реакции кода на отложенное изменение, а не новое воспроизведение аппаратного случая.

Проверка нового временного допуска 2026-09-29 на `Mac15,7`/macOS 27.0: прямой запуск `observe-baseline --read-only` из отдельного процесса вне песочницы, без `sudo`. Получен 61 исходный снимок за 60,663159 секунды (`7832.058583` → `7892.721742`), интервалы завершённых чтений 1,003648–1,016329 секунды. Все `Ftst=0`, режимы `[3,3]`, цели и RPM `[0,0]`; финал `complete/stable`, код 0. Источник — полный локальный JSONL вывод; записи SMC не было. Настоящий сон и намеренное зависание IOKit в этой новой CLI проверке не выполнялись; соответствующие отказы проверены подставными часами и чтениями.

## 5. Scenarios (BDD / test cases)

### Scenario: Исходное состояние сохраняется весь интервал
* **Given:** точная модель и версия ОС, обязательные ключи читаются.
* **When:** 61 снимок остаётся исходным.
* **Then:** команда печатает `complete` со статусом `stable` и завершается успешно.
* **Manual:** проверено запуском 2026-09-26 на `Mac15,7`/macOS 27.0, §3a.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_requires_every_sample`

### Scenario: Между исходными снимками есть длительный разрыв
* **Given:** принят первый исходный снимок.
* **When:** следующий снимок получен через 21 секунду.
* **Then:** цикл завершается с `timing_failed`; исходные ключи после разрыва не подтверждают непрерывное окно.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_rejects_a_gap_between_samples`

### Scenario: Первое чтение заняло слишком долго
* **Given:** наблюдение запускается с рабочими часами.
* **When:** первое чтение занимает шесть секунд.
* **Then:** оно не принимается в окно, результат — `timing_failed`.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_rejects_a_slow_first_read`

### Scenario: Снимки слишком частые или часы идут назад
* **Given:** первый исходный снимок принят.
* **When:** следующий интервал составляет 0,5 секунды либо отметка времени уменьшается.
* **Then:** цикл завершается с `timing_failed` без успешного подтверждения.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_rejects_short_or_reversed_intervals`

### Scenario: 61 снимок не образует полную минуту
* **Given:** все 61 снимок исходные, каждый интервал по 0,99 секунды допустим отдельно.
* **When:** между первым и последним прошло менее 60 секунд.
* **Then:** цикл сообщает `timing_failed`, а не `stable`.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_requires_elapsed_time_for_the_full_window`

### Scenario: Время неизвестно до первого чтения
* **Given:** часы вернули отрицательное, бесконечное или нечисловое значение.
* **When:** запрашивается начало наблюдения.
* **Then:** цикл завершается с `timing_failed` до чтения; отсутствующий callback часов даёт внутренний отказ.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_rejects_an_invalid_clock`

### Scenario: Состояние изменилось между снимками
* **Given:** исходный снимок прочитан.
* **When:** следующий снимок показывает `Ftst=1`, режим не `3` или ненулевую цель.
* **Then:** команда печатает `alert` и завершается с ошибкой.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_catches_delayed_ftst_change`, `prototype/smc-write-trial/trial_actions_test.c#baseline_observation_rejects_changed_state`

### Scenario: Обязательное чтение не удалось
* **Given:** наблюдение началось.
* **When:** один из обязательных ключей недоступен.
* **Then:** команда печатает `alert` с `read_failed` и завершается с ошибкой.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_stops_on_read_failure`

### Scenario: Наблюдение прервано или ожидание не удалось
* **Given:** хотя бы один исходный снимок прочитан.
* **When:** процесс получает прерывание либо ожидание следующего снимка завершается ошибкой.
* **Then:** команда печатает `alert` с причиной `interrupted` либо `wait_failed` и завершается с ошибкой, без `complete/stable`.
* **Automated:** `prototype/smc-write-trial/trial_actions_test.c#baseline_window_stops_on_interruption_or_wait_failure`

## 6. Limits

Этот режим не является внешним watchdog: он завершается после 61 снимка и не может восстановить состояние при ошибке, аварии процесса, сне или позднейшем изменении SMC. Фактическая длительность может превышать минуту. Проверка времени обнаруживает разрыв после возврата из блокирующего чтения, но не прерывает сам вызов IOKit. Короткий сон внутри допустимого интервала не определяется отдельным системным событием. Длительность задержки после аппаратной записи пока неизвестна; само наблюдение без новой пробы не определит её предел.
