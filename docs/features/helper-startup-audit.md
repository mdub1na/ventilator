# Read-only аудит SMC при запуске helper

## 1. Назначение

После `SIGKILL` память минутного watcher исчезает: новый daemon отвечает `idle` и `samples=0`. Пустой watcher не сообщает, какое состояние SMC увидел процесс при старте. Отдельный audit читает фиксированные ключи **один раз до запуска XPC listener** и сохраняет результат на время жизни daemon. Он ничего не записывает и никогда не разрешает управление вентиляторами.

## 2. Правила

1. При каждом запуске подписанного daemon `StartupAuditController` вызывает тот же fixed-key reader, который проверен для `fetchBaselineWithReply`. Снимок и PID захватываются до `listener resume`; последующие XPC запросы не повторяют чтение startup audit.
2. Один исходный снимок даёт `state=system_at_start`, изменённый `Ftst`, режим или цель — `changed_at_start`. Ошибка чтения, неподдерживаемая модель/ОС или ошибка монотонных часов дают `read_failed` с ограниченным кодом причины. Ни одно состояние не обозначает устойчивое восстановление после записи.
3. Ответ содержит `control_allowed=false` при любом состоянии. Подписанный клиент проверяет точную форму ответа и сам пересчитывает `baseline`; ложное `system_at_start`, некорректный снимок или `control_allowed=true` отвергаются. Неправдоподобная конечная температура вне 10–115 °C передаётся как `null` в соответствующей позиции, не скрывая прочитанные ключи управления. Метод не принимает аргументов и не открывает произвольные SMC-ключи.
4. После аварии daemon новый PID создаёт собственный startup audit. Прежний снимок не переносится; разница PID и монотонных отметок проверяется отдельной пробой. Обычный UI сам службу не регистрирует.
5. При полном перезапуске Mac тестовый пакет должен оставаться доступен на диске. Проверка использует изменение `kern.boottime`, а не неравенство PID: числовой PID может повториться в другой загрузке.
6. Для отдельной проверки самостоятельного старта только сохраняемый тестовый пакет задаёт `RunAtLoad=true`. PID UID 0 читается из `launchctl` до первого XPC-запроса подписанного клиента после регистрации и после перезагрузки. Это не устанавливает, запустилась ли служба до входа пользователя.

## 3. Локальный контракт

`fetchStartupAuditWithReply` возвращает `protocol_version`, `daemon_pid`, `state`, `control_allowed`. При успешном чтении добавляются `available=true`, модель/версия ОС, монотонная отметка и фиксированный снимок `Ftst`, двух режимов, целей, RPM и трёх температур. Каждая температура имеет числовое значение в диапазоне 10–115 °C либо `null`, если конечное значение вне диапазона. Ошибка обязательного чтения по-прежнему даёт `available=false` и `reason`, без выдуманных показаний. Диагностическая команда временной подписанной копии: `Ventilator --helper-startup-audit`. Её код 0 означает только валидный XPC ответ, а не разрешение на управление.

## 4. Проверка

`StartupAuditControllerTest.m` подставляет исходный, изменённый и ошибочный reader, проверяет единственное чтение на объект и валидацию XPC ответа.

Первый запуск временной Apple Development подписанной копии на `Mac15,7`/macOS 27.0 вернул из UID 0 daemon PID `49002` `state=system_at_start`, `control_allowed=false`, `Ftst=0`, режимы `[3,3]`, цели `[0,0]`, RPM `[0,0]`. Монотонная отметка startup audit `78494523338000` предшествовала отметке свежего `fetchBaseline` `78494651086000`. Оба чужих клиента были отклонены. После пользовательского запуска `startup-audit-crash-run` независимый запрос подтвердил новый PID `49648` и новый audit с отметкой `78734889463000`, тем же исходным SMC состоянием и `control_allowed=false`. Служба снята с регистрации (`notRegistered`, `system-service=absent`), тестовый пакет удалён, фоновая активность возвращена в «выкл.». Записи в SMC не было.

Отдельная проба полной перезагрузки использовала сохраняемый подписанный пакет и `reboot-before`: до неё `kern.boottime=1790359888`, daemon PID `57992` вернул `system_at_start`, `control_allowed=false`, `Ftst=0`, режимы `[3,3]`, цели `[0,0]`. Перед перезагрузкой `reboot-after` правильно отказался принимать ту же загрузку. После пользовательской перезагрузки `kern.boottime=1790441319`; запрос из подписанного клиента получил новый startup audit от UID 0 daemon PID `1701` с `system_at_start`, `control_allowed=false` и тем же исходным SMC состоянием. Новая монотонная отметка `79509884000` соответствует новой загрузке; отдельный свежий снимок также показал исходное состояние. Запрос проверяет доступность daemon **после обращения клиента**, но не доказывает, что daemon запустился сам до входа пользователя. `unregister` подтвердил `notRegistered` и отсутствие системной службы, пакет и каталог пробы удалены; пункт Ventilator исчез из списка фоновых объектов. Записи в SMC не было.

Отдельная проба с `RunAtLoad=true` на `Mac15,7`/macOS 27.0 сначала подтвердила PID `6923` и UID 0 из `launchctl` **до первого XPC-запроса**; audit того же PID вернул `system_at_start`, `control_allowed=false`, `Ftst=0`, режимы `[3,3]`, цели `[0,0]`. После пользовательской перезагрузки `kern.boottime` изменился `1790441319 → 1790442502`. `reboot-after` до XPC обнаружил работающий UID 0 daemon PID `298`; его audit снова показал исходное состояние управления и `control_allowed=false`. Раннее чтение `Tg0D=-1,95 °C` не является правдоподобной температурой GPU: свежий снимок спустя примерно 63 секунды вернул `49,48 °C`. Поэтому стартовый audit пригоден для фиксации состояния ключей управления в этой пробе, но его температуры нельзя без проверки показывать пользователю. `unregister` подтвердил `notRegistered` и отсутствие системной службы, временный пакет удалён; фоновый объект Ventilator исчез из списка. Записи в SMC не было. Проверка выполнена после входа пользователя и не доказывает старт daemon до входа.

## 5. Сценарии

### Scenario: Исходное состояние при запуске не разрешает управление
* **Given:** первый снимок содержит `Ftst=0`, режимы `[3,3]` и нулевые цели.
* **When:** daemon создаёт startup audit до запуска listener.
* **Then:** ответ содержит `system_at_start`, один монотонный снимок и `control_allowed=false`; повторный запрос не читает SMC снова.
* **Automated:** `prototype/helper-ipc/StartupAuditControllerTest.m`.

### Scenario: Изменённое состояние или отказ чтения обнаружены при запуске
* **Given:** первый снимок изменён либо reader возвращает ошибку.
* **When:** daemon создаёт startup audit.
* **Then:** ответ содержит `changed_at_start` с фактическим снимком либо `read_failed` без него; клиент не принимает ложное исходное состояние.
* **Automated:** `prototype/helper-ipc/StartupAuditControllerTest.m`.

### Scenario: Перезапущенный daemon получает новый audit
* **Given:** подписанный UID 0 daemon вернул startup audit и собственный PID.
* **When:** администратор завершает только тестовую read-only службу через `SIGKILL`.
* **Then:** новый PID возвращает более поздний startup audit со свежим фиксированным снимком.
* **Manual:** `prototype/helper-ipc/integrated-probe.sh startup-audit-crash-run`; на `Mac15,7`/macOS 27.0 проверены PID `49002 → 49648` и более поздняя отметка нового audit.

### Scenario: После перезагрузки Mac доступен новый startup audit
* **Given:** подписанный read-only daemon зарегистрирован из сохраняемого тестового пакета, а `reboot-before` записал текущую загрузку и исходный снимок.
* **When:** Mac полностью перезагружается и подписанный клиент вызывает `reboot-after`.
* **Then:** системное время загрузки изменилось, зарегистрированный UID 0 daemon возвращает свой startup audit с `control_allowed=false`, а отдельное свежее чтение показывает исходное состояние; после проверки службу и пакет удаляют.
* **Manual:** `prototype/helper-ipc/integrated-probe.sh prepare-reboot`, `reboot-before`, `reboot-after`; `Mac15,7`/macOS 27.0, новый `kern.boottime` и UID 0 PID `57992 → 1701` подтверждены.

### Scenario: Read-only daemon работает до первого XPC запроса клиента
* **Given:** сохраняемая подписанная копия зарегистрировала LaunchDaemon с `RunAtLoad=true`, а macOS разрешила фоновую активность.
* **When:** `eager-check` читает PID из системного launchd до своего первого XPC-запроса; после перезагрузки `reboot-after` делает то же до запроса.
* **Then:** оба раза запущен UID 0 `daemon-status`, и последующий startup audit приходит от того же PID с `control_allowed=false`; после проверки службу и пакет удаляют.
* **Manual:** `prototype/helper-ipc/integrated-probe.sh eager-check` и `reboot-after`; на `Mac15,7`/macOS 27.0 получены PID `6923 → 298` до первого XPC каждого запуска. Проверка после входа в macOS не доказывает запуск до входа.

### Scenario: Раннее неправдоподобное показание GPU недоступно
* **Given:** первый read-only снимок имеет исходные `Ftst`, режимы и цели, но `Tg0D=-1,95 °C`.
* **When:** daemon формирует startup audit, а подписанный клиент проверяет ответ.
* **Then:** `state=system_at_start` классифицирует только ключи управления, `control_allowed=false`, в позиции `Tg0D` стоит `null`; сырое отрицательное число клиент отвергает.
* **Automated:** `prototype/helper-ipc/StartupAuditControllerTest.m`, `prototype/helper-ipc/HelperBaselineValidationTest.m`.

## 6. Ограничения

Audit содержит один последовательный снимок; отложенное изменение может возникнуть после него. При раннем запуске `Tg0D` однажды вернул `−1,95 °C`, затем нормальное значение; теперь такое поле передаётся как `null`. Обработка `null` проверена подставленным снимком; повторный запуск в самый ранний момент загрузки с новой версией не проводился. `system_at_start` классифицирует ключи управления, а не достоверность температур. Минутный watcher остаётся отдельным наблюдением. Даже `system_at_start` не доказывает восстановление после записи, поэтому интерфейс управления остаётся заблокированным.
