# Минутное наблюдение исходного SMC-состояния внутри helper

## 1. Назначение

После первой пробы `Ftst=1` немедленное чтение показало исходное состояние, а более позднее независимое чтение — изменённое. Подписанный read-only daemon теперь может продолжать фиксированное наблюдение после завершения инициировавшего JVM-процесса. Это прототип обнаружения отложенного изменения для M2-02, без записи в SMC и без автоматического восстановления.

## 2. Правила

1. `startBaselineWatchWithReply` и `fetchBaselineWatchWithReply` не принимают аргументов. Методы доступны только клиенту, прошедшему существующую двустороннюю проверку подписи. Обычный запуск UI службу не регистрирует.
2. На `Mac15,7`/macOS 27.0 daemon читает только фиксированные `Ftst`, режимы, цели, фактические RPM и три температуры. Первое чтение — отметка 0, затем чтения с секундными таймерами до отметки 60: при успехе 61 снимок и `state=stable`.
3. Состояние `changed` устанавливается сразу при `Ftst≠0`, режиме не `3` или цели с абсолютным значением выше 1 RPM. Оно остаётся до завершения daemon, даже если позднее SMC снова показывает исходное состояние. Нулевые фактические RPM допустимы.
4. Ошибка обязательного чтения или нарушения последовательности приводит к `read_failed`. Клиент не превращает это состояние в `stable`; ответ с ложным утверждением `stable` отклоняется его валидатором.
5. Наблюдение хранится в процессе daemon и продолжается после окончания XPC запроса и выхода инициировавшего JVM-процесса. Новый запрос `fetchBaselineWatchWithReply` читает состояние без перезапуска. Повторный `start` во время наблюдения или после `changed`/`read_failed` не очищает результат.
6. Таймеры отсчитывают интервалы между снимками. Фактическая продолжительность может быть больше 60 секунд; тестовый скрипт ждёт `stable` с конечным лимитом вместо вывода по одной паузе.

## 3. Локальный контракт

Диагностические команды во временной подписанной копии приложения:

```text
Ventilator --helper-watch-start
Ventilator --helper-watch-status
```

Ответ содержит `protocol_version`, `state`, `samples`, `last_second`, `daemon_pid`, монотонное время начала и последнего снимка. Пока есть действительный снимок, он также содержит `baseline`, `Ftst`, два режима, две цели, два фактических RPM и три температуры. При `read_failed` добавляется ограниченный код причины, без показаний, которые могли устареть. Метод не принимает произвольный SMC-ключ или RPM.

## 4. Проверка

`BaselineWatchTest.c` моделирует отложенный `Ftst=1` на третьем снимке, стабильное окно 0–60 и ошибку чтения. `HelperWatchValidationTest.m` проверяет, что клиент отвергает преждевременное `stable` и ложное `baseline=true` при ненулевых целях.

На `Mac15,7`/macOS 27.0 временная Apple Development подписанная копия настоящего `Ventilator.app` запустила watcher внутри UID 0 daemon. Первый тестовый скрипт ошибочно счёл фиксированную паузу 62 секунды достаточной: в тот момент daemon с PID `1809` продолжал работать, `samples=57`, `state=running`; отдельный последующий JVM-запрос увидел `samples=61`, `last_second=60`, `state=stable` от того же PID. Скрипт исправлен на ограниченное ожидание состояния.

Повторная проба с исправленным `integrated-probe.sh watch` завершилась кодом 0. Первый JVM-процесс получил `state=running`, `samples=1` и завершился. Новый процесс получил `state=stable`, `samples=61`, `last_second=60` от прежнего UID 0 daemon PID `2612`; монотонное время между первым и последним снимками составило 66,09 секунды. Последний снимок: `Ftst=0`, режимы `[3,3]`, цели `[0,0]`, RPM `[0,0]`, `TCMz=74,64`, `Tg0D=50,11`, `TH0a=33,25 °C`. `unregister` вернул `notRegistered`, системная служба отсутствовала, временный пакет удалён, фоновая активность Ventilator возвращена в исходное «выкл.». SMC write selector не использовался. Наблюдение после новой записи и восстановление не проверялись.

## 5. Сценарии

### Scenario: Отложенное изменение остаётся обнаруженным
* **Given:** первый и второй снимки показывают исходное состояние.
* **When:** третий снимок содержит `Ftst=1`, изменённый режим и ненулевую цель.
* **Then:** состояние становится `changed` и не сбрасывается последующим исходным снимком.
* **Automated:** `prototype/helper-ipc/BaselineWatchTest.c`.

### Scenario: Наблюдение завершается только после 61 исходного снимка
* **Given:** signed daemon запущен и начальное состояние исходное.
* **When:** 60 следующих чтений также исходные.
* **Then:** `state=stable`, `samples=61`, `last_second=60`; завершение клиента после `start` не останавливает daemon.
* **Automated:** `prototype/helper-ipc/BaselineWatchTest.c`, `prototype/helper-ipc/HelperWatchValidationTest.m`.
* **Manual:** `integrated-probe.sh watch` на `Mac15,7`/macOS 27.0, результат в §4.

### Scenario: Ошибка чтения не считается восстановлением
* **Given:** наблюдение началось с исходного снимка.
* **When:** обязательное чтение не удалось.
* **Then:** daemon сообщает `read_failed`, а клиент не принимает это как `stable`.
* **Automated:** `prototype/helper-ipc/BaselineWatchTest.c`.

## 6. Ограничения

Чтения последовательны, не атомарны и происходят в отдельные моменты. Состояние между снимками может быть пропущено. Наблюдатель не восстанавливает управление вентиляторами; при аварии самого daemon накопленное состояние теряется. `stable` описывает только проверенный интервал и не доказывает безопасность будущей записи `Ftst`.
