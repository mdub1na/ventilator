# Compose Desktop окно мониторинга

Окно и строка меню для `Mac15,7` на Kotlin/JVM 2.4.20, Compose Multiplatform Desktop 1.12.0, Material 3 `1.12.0-alpha03` с `MaterialExpressiveTheme` и Swift/AppKit. Источник данных — [локальный reader](../smc-read/README.md) на C/IOKit через [модель Kotlin](../kotlin-read/README.md). Запись в SMC отсутствует.

Окно обновляет температуры CPU (`TCMz`), GPU (`Tg0D`) и SSD (`TH0a`) вместе с фактическими RPM двух вентиляторов каждые 2 секунды. Три температурные карточки расположены над карточками вентиляторов с индивидуальными пятисегментными шкалами. `Tg0D` вырос примерно с 45 до 68 °C при 22-секундной нагрузке GPU на `Mac15,7`; `TH0a` вырос примерно с 29,4 до 39,6 °C при отдельной нагрузке внутреннего накопителя. В карточках видны сырые ключи. Разделы других температур и диагностики датчиков убраны из окна; команда reader для полного списка ключей сохранена для исследований.

При ручном запуске открывается мониторинг. Шестерёнка справа вверху или пункт «Настройки» в контекстном меню открывают отдельный экран настройки автозапуска; стрелка возвращает мониторинг. Обычный щелчок по значку переключает видимость окна; его закрытие красной кнопкой или пункт «Скрыть окно» оставляет процесс и опрос работающими. Пункт «Открыть окно» показывает окно снова, «Выход» завершает оба процесса. Контекстное меню открывается нажатием двумя пальцами по значку. Kotlin передаёт снимок в AppKit через локальный stdin/stdout дочернего процесса: Swift не читает SMC и не рассчитывает уровни повторно. Значок объединяет вентилятор, пятиделённую шкалу по максимальному из двух индивидуальных уровней и `TCMz` в °C.

На экране настроек находится переключатель «Запускать при входе в macOS». Вложенная Objective-C/JNI библиотека обращается к `SMAppService.mainAppService` из основного процесса, поэтому статус отражает регистрацию в macOS. Если системе нужно разрешение, переключатель остаётся выключенным и появляется кнопка перехода в системные настройки. После подтверждённого включения приложение запустилось автоматически при следующем входе пользователя на `Mac15,7`, показав значок при скрытом окне. Настройка недоступна при `gradle run`, поскольку этот путь не запускает `.app`.

Нужны macOS Apple Silicon, JDK 25, Gradle, Xcode Command Line Tools и доступ к зависимостям Gradle для первого запуска. Из этого каталога:

```bash
gradle :test
gradle :run
gradle createDistributable -Pcompose.desktop.packaging.checkJdkVendor=false
```

`gradle :run` сам собирает `smc-read` и `status-item-bridge` и использует соседние каталоги исходников. `createDistributable` включает оба исполняемых файла и `liblogin-item.dylib` в `build/compose/binaries/main/app/Ventilator.app`; флаг проверки vendor нужен для локального JDK 25. Для прямого запуска собранного пакета используйте Finder. Reader не требует `sudo` на проверенной модели. Перед повторной упаковкой завершите открытую копию приложения: `jpackage` не может переподписать её работающий Java runtime.

Это локальная сборка с ad hoc подписью для проверки, а не готовый дистрибутив. Регистрация автозапуска, её отмена, запрос разрешения, запуск после нового входа со скрытым окном, отсутствие запуска после выключения и оба пути к экрану настроек проверены на `Mac15,7`. Подпись Developer ID и нотарификация — M3, управление скоростью — M2. Исходники [изолированного AppKit прототипа](../menu-bar/README.md) сохранены для проверки рисунка; при обычном запуске `.app` создаётся один статусный элемент.
